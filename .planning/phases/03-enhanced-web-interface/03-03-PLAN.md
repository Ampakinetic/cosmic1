  2. process() — called from loop() on a 1s millis timer; evaluate on snapshot seq advances and time progression (millis-idiom, never delay):
  - ALTITUDE (warning): active while lroundf(altitudeM * 100) > altWarnM * 100 (integer cm comparison — strictly above; equal does not fire). Auto-clear on resolve; ALERT_REARM_COOLDOWN_MS = 30000 before the same warning may re-fire.
  - BATTERY (critical): batteryValid && batteryMv < lroundf(battLowV * 1000) (integer mV). Latches until acknowledged; re-fire re-latches.
  - GPS_LOST (critical): latch when a valid fix was previously seen and no valid fix has arrived for more than gpsLostS seconds (measure from the last snapshot with gpsValid true — sustained age, so transfer-delayed beacons do not false-fire, Pitfall 9).
  - LANDING (critical): maintain launch baseline (altitude of the first valid fix) and max altitude; when (maxAlt - baseline) > 50 m AND |rate| < landingRateMps continuously for landingStableS, latch.
  - RATE (warning): rate = (altitudeM_now - altitudeM_prev) * 1000.0f / elapsedMs from consecutive beacons, compared unrounded and strictly: |rate| > rateLimitMps -> active (equal does not fire); auto-clear + cooldown.
  - SIGNAL (warning): sliding 60 s window of seq-gap accounting: count received beacons when snapshot.seq advances; gaps = (seq_now - seq_prev wrapped mod 65536) - 1; lossPct = missed / expected * 100 with expected = elapsed / TELEMETRY_BEACON_INTERVAL_MS. Active while lossPct > beaconLossPct; auto-clear + cooldown. Derived metric only — the engine never reads the radio driver.
  All conditions include their data-age terms: nothing evaluates from a stale snapshot as if fresh (the GPS_LOST age logic owns that semantics; ALTITUDE/RATE require the snapshot's receivedMs within 3x the beacon cadence).
