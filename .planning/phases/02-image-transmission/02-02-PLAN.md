  Extend ImageTxManager:
  - Enqueue gate (Q4 resolution): if the full-image length exceeds MAX_IMAGE_SIZE (50000), do not arm a full transfer for that entry — log a warning naming the image ID and size; the thumbnail still pushes and the entry skips announcement. The base never sees a manifest for it, so no pull is attempted (airtime not wasted on a doomed transfer).
  - Entry state machine (extends the 02-01 states, does not replace them): after the thumbnail push completes, emit the FULL_IMAGE manifest ONCE (totalSize = full length, chunkSize 200, totalChunks = ceil, crc32 over the full buffer, captureTimeMs, settings trailer) and mark the entry ANNOUNCED. From then on the entry serves chunks only through window context — never free-runs (Pitfall 5: the half-duplex link is serialized by the base asking; the balloon does not volunteer chunks outside a requested window).
  - Public handleWindowRequest(const uint8_t* payload, size_t len): decode PayloadImageWindowRequest (big-endian via readUint16); validate imageId maps to a queued ANNOUNCED entry whose full transfer is armed, startChunk + count <= totalChunks (clamp or reject), count <= IMG_WINDOW_MAX_CHUNKS, 1 <= count. Arm a per-entry window context {start, count, nextIndex}. Idempotency (Pitfall 10): arming resets nextIndex to startChunk — a duplicate or re-requested window simply re-sends the same indices; no ID allocation, no queue mutation. Return an enum/bool the handler maps to ACK vs NACK_INVALID/NACK_BUSY so the existing response path answers the base.
  - process() chunk service: when a window is armed on the highest-priority eligible entry (FIFO: earliest enqueued ANNOUNCED entry with an armed window — D-19 order), transmit the next unsent chunk of that window (one transmit per pass, full buffer offset startChunk*200 slice, dataLen = min(200, remaining bytes of the image)). When the window's last chunk is transmitted, clear the armed context. Only one entry is actively servicing at a time; a window request for a NEWER image ID implicitly completes older ANNOUNCED entries (FIFO pull order means the base has moved on) — evict them and free their buffers.
  - Eviction policy (bounded memory): (a) queue depth > IMG_TX_QUEUE_DEPTH drops the OLDEST entry with a Serial warning; (b) newer-ID window request evicts older entries as above; (c) entries older than IMG_ENTRY_TTL_MS (15 min) are evicted with a log. Every eviction frees both PSRAM buffers.

  Extend src/command_handler.cpp command switch: case CameraCommand::IMAGE_WINDOW_REQUEST — read the pending command payload, call ImageTx().handleWindowRequest(...), map the result to the existing CommandResult/response machinery (ACK on armed; NACK_INVALID when the image ID is unknown/evicted or the range is out of bounds; NACK_BUSY when another entry's window is mid-service — the base retries with its existing timeout/retry machinery). This keeps every response flowing through createResponsePacket (0x11 first-field) and the tracked-command contract unchanged.
