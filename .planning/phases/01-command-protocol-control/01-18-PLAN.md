<objective>
Close the code half of the G-01-7 residual: command-frame survivability under unspaced-capture chunk storms. Command transmits on the base (first attempts and timeout retries) acquire a channel-quiet gate — they hold while inbound 0x13 chunk frames arrived within a small window, consuming nothing, bounded by a best-effort escape, then transmit in the stream's natural pause.

Purpose: session 5 proved every balloon-side failure mode eliminated, but the third unspaced CAPTURE_NOW (seq=6) lost all 4 transmissions (original + retries 1/3, 2/3, 3/3) while 217-byte chunk frames flowed continuously — a 16-byte command frame transmitted into a half-duplex channel the balloon was occupying has near-zero landing probability, and the honest 3-retry budget burned in ~16 s of storm. The named lever (01-UAT.md G-01-7): "command air-priority or command-burst pacing during window service". This plan implements it base-side: never transmit a command into an active inbound chunk stream; wait for the quiet gap that necessarily follows (every window completes, every push drains), then transmit. The balloon-side periodic-yield alternative is deliberately NOT taken — single-lever discipline (the 01-08 lesson); if the bench still fails, the yield is the named next lever.

Output: the quiet gate wired at both transmit sites with hold/release/best-effort logs (bench discriminators); both firmware targets green; harness green. No gap-status flips this plan (bench closure is 01-20).

Spec-less probe fallback: recorded visible skip — this phase has no machine-mapped requirement IDs (phase_req_ids null), so no probe predicates were generated this run.
