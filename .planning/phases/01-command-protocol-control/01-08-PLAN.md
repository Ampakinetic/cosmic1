<objective>
Close the code half of UAT gap G-01-3 (blocker, Test 3): image-transfer timeouts caused by E32 transport failure on the system's only multi-RF-packet frames (216-byte 0x13 chunks sub-pack into 4x58-byte RF packets at the factory-default 2.4 kbps air rate; commands/ACKs/beacons/manifests are single-packet, exactly matching the observed works/doesn't-work split).

Purpose: the debug session (storage-unavailable-image-tx-timeout.md) exonerated all transfer logic and narrowed symptom B to the E32 transport layer, with ranked mechanisms B1 (air-rate config exceeds the 5 s AUX bound), B2 (4x per-packet loss defeats 3-pass ARQ), B3 (PA current sag), B4 (push-stream saturation starving window ARQ). Raising the air data rate is the one mitigation that helps B1, B2, and B4 simultaneously (and shortens B3's exposure window) — but the driver's config commands are a non-functional stub: writeConfig (e32_lora.cpp:290-314) sends no 0xC0 command byte and omits the CHAN/OPTION registers, so no code path can currently change the module's configuration. This plan makes module configuration real and enforces the target rate at every boot on both boards.
Output: working register-level read/write with echo verification, boot-time decoded-config logging, and fail-open air-rate enforcement at 9.6 kbps — the firmware the 01-09 bench session flashes to re-test transfers.
</objective>
