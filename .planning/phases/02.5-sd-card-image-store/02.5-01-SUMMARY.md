# Phase 2.5 Plan 01: Balloon SD File-Store Tracer Slice Summary

**Balloon captures now persist full+thumbnail JPEG and a META commit record to the SD card BEFORE any manifest goes on air, and every transferred chunk byte is read from the card file — the volatile PSRAM queue survives only as the honestly-labeled SD-write-failure fallback.**

## Accomplishments

- **BalloonSdStore module** (include/sd_store_balloon.h + src/sd_store_balloon.cpp): SD_MMC 1-bit transport on the operator-locked pins (CLK=39/CMD=38/D0=40, 20 MHz, setPins-before-begin per the arduino-esp32 3.x GPIO-matrix requirement), degrade-never-halt begin(), idempotent /images mkdir, /images/IMG_%05u.JPG + _T.JPG + .META layout, 36-byte packed BalloonCaptureRecord META with magic validation, free-space pre-check with 64 KiB headroom, META-written-LAST commit ordering, readChunk with offset-past-EOF guard, markDelivered one-byte in-place flags update, honest four-state BalloonSdStoreStatus.
- **ImageTxManager file-backed rework**: enqueueCapture now attempts persistCapture first and branches three ways — PERSISTED fills the entry with null buffers (card is the byte source); CARD_FULL refuses honestly with no entry and no fallback; IO_ERROR runs the legacy ps_malloc admission verbatim behind `entry.volatileFallback = true` and the named "image lost on reboot" line. pushThumbChunk and serviceWindowChunk branch on volatileFallback: file-backed entries serve a stack chunkBuf via readChunk, and a readChunk false takes the EXISTING transmit-failure semantics (same-index retry, bounded skip with the "SD read failed" named log). WR-08 success-gated cursors, RX-settle, kind-selected sources, and SERVED semantics preserved byte-for-byte — only the byte SOURCE changed.
- **WR-02 fold**: the per-entry receipt stamp and re-announce budget re-arm in handleWindowRequest moved after per-kind range validation + tail clamp, so only a fully validated, armable request counts as receipt evidence.
- **WR-01 fold**: the IDLE0 stack instrument gained s_idle0HasSample, so a genuine zero watermark — the exact overflow signature it exists to catch — is now printable instead of hidden by the != 0 sentinel.
- **Balloon wiring + isolation**: BalloonSdStoreTx().begin() slots between Camera().begin() and ImageTx().begin(); the base env excludes sd_store_balloon.cpp in platformio.ini; zero BalloonSdStore references in any base-side source.
- **IMG_MAX_IMAGE_SIZE comment re-named** (image_protocol.h): the 50000 cap now names its real reason — the frozen wire and the base's own MAX_IMAGE_SIZE validation — not a balloon RAM limit (no longer true under the file-backed pipeline).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] META record pinned at 36 bytes, not the plan's 32**
- **Found during:** Task 1
- **Issue:** The plan specified a "fixed 32-byte" BalloonCaptureRecord with static_assert(sizeof == 32), but its named fields alone total 33 bytes (2+2+1+1 + 5x4 + 7 camera-settings bytes) — a 32-byte pin was arithmetically impossible with any packing.
- **Fix:** Implemented all specified fields plus the specified 3 pad bytes = 36 bytes, static_assert(sizeof == 36), with the arithmetic documented in the header's card-format note. No cross-version contract breaks: the card is read back only by this firmware.
- **Files modified:** include/sd_store_balloon.h
