<objective>
Tracer slice: re-architect the balloon image pipeline around a FAT32 SD-card file store so one full path works end-to-end — CAPTURE_NOW persists thumbnail + full JPEG to the card BEFORE the manifest, the base receives the thumbnail push, arms a FULL window, and completes the image with CRC verified, with every chunk read from the card file, no image payload in RAM on the normal path (ROADMAP Phase 2.5 goal, quoted verbatim as the MVP story frame; the ROADMAP Goal line is not in user-story format — this plan uses the goal text itself as the story, per the locked operator decisions in CONTEXT.md).

Purpose: 14 consecutive gap-closure rounds (sessions #5–#14) all patched the volatile PSRAM queue's eviction/supersede defect class. The file-backed design retires the class: capture→file before manifest, window reads from file, and (plan 02.5-02) undelivered images survive reboot. The volatile queue survives ONLY as the honestly-labeled SD-write-failure fallback (operator decision D-03, locked 2026-08-29).

Output: `include/sd_store_balloon.h` + `src/sd_store_balloon.cpp` (new balloon-side SD store module), reworked `image_tx_manager.{h,cpp}` (file-backed normal path + volatile fallback branch + WR-02 fix), wired `main_balloon.cpp` (+ WR-01 fix), base-env build exclusion in `platformio.ini`. BalloonCaptureRecord — fixed 32-byte binary struct (packed, little-endian native; the card is read back only by this firmware — document that in the header): u16 magic SD_STORE_META_MAGIC (pick a constant, e.g. 0x4D31, and validate it on read), u16 imageId, u8 flags (bit0 SD_ST_DELIV_THUMB, bit1 SD_ST_DELIV_FULL — zero at capture), u8 captureSource, u32 captureTimeMs, u32 fullLength, u32 fullCrc32, u32 thumbLength, u32 thumbCrc32, 7 camera-settings bytes (resolution, quality, brightness, contrast, saturation, exposure, wbMode — ImageTxSettings layout), 3 pad bytes to 32. static_assert(sizeof == 32).

persistCapture(const imageId, captureSource, captureTimeMs, settings, fullBytes/fullLen, thumbBytes/thumbLen) -> PersistOutcome enum { PERSISTED, CARD_FULL, IO_ERROR }:
1. Free-space pre-check BEFORE any write: required = fullLen + thumbLen + 2*sizeof(record) + SD_STORE_MIN_FREE_BYTES headroom (constant 65536); if SD_MMC.totalBytes() - SD_MMC.usedBytes() < required -> return CARD_FULL with zero files written (the refusal leaves no partials).
2. Write IMG_%05u.JPG (full bytes) and IMG_%05u_T.JPG (thumb bytes) — FILE_WRITE truncate-create then write then close.
3. Write the META record LAST as the commit marker (a boot rescan trusts an image only when META validates — plan 02.5-02 builds on this ordering; torn JPGs-without-META are honestly skipped, never fabricated).
Any open/write failure mid-sequence: close handles, log the failed path, set status.writeFailed, return IO_ERROR (do NOT attempt to delete the partial files — keep-everything archive; the boot rescan classifies them).

readChunk(imageId, kind, chunkIndex, uint8_t* out, capacity IMG_CHUNK_PAYLOAD_SIZE, size_t* outLen) -> bool: build the kind's path, SD_MMC.open (per-call open — justified in a comment: one window services at a time, a chunk transmit costs 250-400 ms at the 9.6 kbps air rate so a 20 MHz open/seek/read is noise), seek(chunkIndex * IMG_CHUNK_PAYLOAD_SIZE), read up to 200, close. Read-failure or short read returns false (caller treats it exactly like a transmit failure — same-index retry, named skip). Guard chunkIndex against the record's stored length (offset past EOF -> false).

markDelivered(imageId, kind): open the META record, read-validate magic + id, set the kind's SD_ST_DELIV_* bit, seek back, write the single flags byte in place (one-byte update — no rewrite).

isAvailable(), getStatus() -> struct BalloonSdStoreStatus { bool available; bool initFailed; bool writeFailed; bool cardFull; } — honest computed state, never a hardcoded OK (IN-03 discipline).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Balloon card -> firmware | Removable FAT32 media: META records and file bytes are untrusted input read back by rescan (plan 02.5-02) and readChunk |
| RF window request -> file read | Inbound 0x13-driven window requests select (id, kind, chunkIndex) used as a file offset |
| Camera capture -> card | Captured bytes cross into persistCapture; a failure here must not fabricate or half-commit transferable state |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.5-01 | Tampering/Information Disclosure | BalloonCaptureRecord META reads (boot rescan, plan 02.5-02) | high | mitigate | Magic + id validation on every record read; size fields cross-checked against actual file sizes before an entry is trusted; unreadable/torn records skipped with a named log, never zero-filled (prohibition 2) |
