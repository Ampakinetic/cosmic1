Serial command in main_balloon: a small non-blocking reader in the main loop (Serial0.available() polled per pass, chars accumulated into a bounded 32-byte line buffer, processed on newline — never Serial.readString*, which blocks the single-threaded loop). Guard rails: the clear runs synchronously in the loop pass (a card with thousands of files takes a few hundred ms of deletes — acceptable at bench cadence; note this in the command's usage line so the operator clears BEFORE a long session, not mid-transfer). No confirmation timeout machinery, no NVS state — the token IS the confirmation.
