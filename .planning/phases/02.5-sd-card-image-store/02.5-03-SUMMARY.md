# Phase 2.5 Plan 03: Honest-Capacity — Card-Full Refusal Gates + SDCLEAR Manual Clear Summary

**A full card now refuses new captures honestly at exactly the two capture triggers (CAPTURE_NOW answers through the frozen NACK_BUSY class, interval/event captures skip with a named log paced by the existing baseline idiom) while telemetry, commands, beacons, and window service of already-stored images continue unaffected — and the keep-everything flight archive gains its ONLY sanctioned deletion surface: the CONFIRM-gated SDCLEAR serial command.**

## Performance

- Estimated 30000 tokens / 2 tasks; actual 5032 tokens (20130-char diff) / 2 tasks — estimate conservative ~6x (the gate reuses 02.5-01's proven arithmetic and the CR-04 refusal shape; the clear is a bounded directory walk mirroring bootRescan).
- Duration ~19 min; 2 task commits + 1 docs commit; 5 source files modified, 0 created (all artifacts are methods/gates on the 02.5-01/02.5-02 modules, exactly as the plan names).

## Accomplishments

- **Shared free-space gate (Task 1, 70203cd)**: `BalloonSdStore::hasHeadroomFor(uint32_t fullLen, uint32_t thumbLen) const` — the exact arithmetic persistCapture's Step-1 pre-check used (capture bytes + both META records + SD_STORE_MIN_FREE_BYTES headroom, 64-bit), now behind one public const query. Returns false also when the store is not mounted (an absent card is the honest card-full-adjacent refusal; the true cause stays visible in the boot log's mount verdict). persistCapture keeps its own pre-check by calling the SAME gate — the pre-capture gates and the persist-time race backstop cannot drift; the refusal log stays byte-identical (free vs required bytes via the shared `requiredSpaceFor`/`cardFreeBytes` helpers). One volume query per capture attempt, never inside the per-chunk loop (T-02.5-09, PRI-03 pacing untouched).
- **CommandHandler refusal gate (Task 1)**: the CAPTURE_NOW branch consults the gate BEFORE any camera work (after the CR-04 camera-ready gate in executeCommand — sibling precondition, composition rules preserved; unknown/cancelled commands behave identically). On refusal: `result.responseType = ResponseType::NACK_BUSY` (the EXISTING class — no new response type anywhere; `ResponseType::` count in command_protocol.h unchanged at 0), message "Capture refused - card full", commandsFailed accounting, and the named balloon log "CommandHandler: capture refused - card full (keep-everything archive; manual clear via SDCLEAR CONFIRM)". The base's D-05/D-07 retry machinery books the failure unchanged. No id allocated, no source stamped, no baseline moved on refusal.
- **AutoCapture skip gate (Task 1)**: `fire()` consults the gate with the worst-case reservation BEFORE any camera work; refusal prints "AutoCapture: capture skipped - card full (image id %u not taken)" (the id the capture would have taken) and returns. The baseline advance moved to sit immediately ahead of the gate — the T-01-09 baseline-before-attempt idiom is what paces refusals (the next interval tick is the retry; no retry/backoff machinery added), which also prevents the 10 Hz event-path machine-gun a pre-baseline gate would have caused.
- **Manual serial clear (Task 2, 8c41585)**: `BalloonSdStore::clearAllImages(const char* confirmToken)` deletes every file inside /images (JPG, _T.JPG, META) via SD_MMC.remove on each walked entry, KEEPING the directory, returning the count removed. Deletion executes ONLY on the literal CONFIRM token — judged at the single named predicate `clearAllImagesTokenMatches` (T-02.5-08: a stray line or typo deletes nothing; the token IS the confirmation, no timeout machinery, no NVS state). Every removal logs ("SdStore: cleared /images/IMG_00042.META" style) plus the summary "SdStore: manual clear removed %u file(s)"; over-long foreign names are skipped with a named line rather than truncated into a wrong-path remove; a failed remove is logged as kept. Not mounted returns 0 with the honest line.
- **SDCLEAR console vocabulary (Task 2)**: a non-blocking reader in the main loop (Serial0.available() polled per pass beside processPacketHandling(), chars accumulated into a bounded 32-byte line buffer, processed on newline; NEVER Serial.readString* — WR-09 no-blocking discipline; an over-long line is discarded whole with one named line). Exact vocabulary: "SDCLEAR CONFIRM" invokes the clear; "SDCLEAR" alone or any other argument prints the usage line with the synchronous-cost note (clear BEFORE a long session, not mid-transfer); anything else falls through untouched. The LoRa wire carries no delete command (protocol frozen, locked decision 5).
- **Wire/telemetry non-interference proven**: the gates touch ONLY the two capture triggers — hasHeadroomFor appears exactly once per gate file and nowhere else (grep 0 in image_tx_manager.cpp and main_balloon.cpp); GET_STATUS, IMAGE_WINDOW_REQUEST, SET_*, and the 0x14 beacon path are byte-untouched; window service of already-stored images continues on a full card (the point of the archive).
