# Phase 2.5 Plan 02: Crash-Resume — Undelivered Images Survive Reboot Summary

**A boot-time rescan of the balloon card rebuilds a bounded RAM index of validated undelivered captures and re-announces them through the EXISTING push/manifest/window machinery, while delivery bits persisted at the two success-gated moments ensure delivered history is never re-announced — reboot turns from data loss into resume.**

## Accomplishments

- **Persisted delivery bookkeeping (Task 1, 7beb182)**: the META delivery bits now flip at exactly the two success-gated moments — the thumbnail bit when a file-backed entry's final thumb chunk transmits successfully inside pushThumbChunk (the same moment completedThumbState is consulted), the FULL bit inside the WR-08-guarded SERVED transition in serviceWindowChunk (`!finalChunkSkipped` precedes the mark — bytes never offered are never delivered). markDelivered failure prints the named "SdStore: delivery flag update failed for image %u kind %u" line and is non-fatal (the documented benign consequence: an idempotent base re-pull). Both-delivered file-backed entries release their RAM slot with the named "fully delivered - RAM index slot released (files kept on card)" line; volatile-fallback entries keep today's TTL behavior unchanged; card files are never touched by bookkeeping (the one-byte META flags update is the designed 02.5-01 mechanism).
- **Boot-time rescan (Task 2, 4190ef0)**: BalloonSdStore::bootRescan() runs ONE bounded openNextFile() walk of /images (the base's buildIndex idiom) collecting IMG_%05u.META candidates, validates each (magic + id, then full-JPG existence/size, thumb-JPG checked only when thumbLength > 0), and classifies honestly: torn captures print "SdStore: torn capture at image %u skipped (no validating META/size mismatch) — file kept on card" (a companion second pass names JPGs whose id has no META file at all); both-delivered records are counted into one summary line; survivors become BalloonResumedRecords sorted ascending by imageId, capped at SD_STORE_MAX_TRACKED 64 keeping the NEWEST ids with the named "oldest ids left un-announced (files kept on card)" degradation. No deletion call exists anywhere in the rescan.
- **Resume admission**: ImageTxManager::admitRescanned() rebuilds the IDENTICAL entry shape enqueueCapture's PERSISTED branch produces (state PUSH_THUMB_MANIFEST when the record carries a thumbnail, ANNOUNCE_FULL/THUMB_PUSHED when it does not; null buffers; META-derived lengths/CRCs/chunk counts; memcpy of the pinned 7-byte settings trailer), admitted FIFO into free slots, collision-guarded, with lastEnqueuedImageId (AutoCap's axis) untouched. Half-delivered records are admitted whole — the existing machinery re-announces both manifests and the base re-pulls idempotently; no per-kind resume cursors exist on the wire.
- **Setup wiring**: main_balloon calls bootRescan + admitRescanned once in setup, only after the store mount verdict (!initFailed — a failed mount prints the honest "no rescan; nothing to resume (volatile fallback regime)" line and skips everything), before the main loop; the summary line "SdStore: rescan found %u undelivered image(s), admitted %u" is the boot-log resume truth.
- **Non-regression**: both environments build SUCCESS; the wire harness exits 0 at HEAD 4190ef0 — zero wire drift, zero base-side change (the base env still excludes the balloon SD module).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical bookkeeping] Vacuous thumbnail obligation retired at persist time**
- **Found during:** Task 1
- **Issue:** A record carrying NO thumbnail (thumbLength 0, capture-time thumbnail failure) can never receive the THUMB delivery bit under the plan's two moments — no push ever runs — so even a fully delivered thumbless capture would be re-announced at EVERY boot forever (airtime waste, base churn, queue occupancy per boot), violating the must-have truth "a later boot does not re-announce delivered images".
- **Fix:** the PERSISTED branch of enqueueCapture marks the THUMB bit immediately at persist time when no thumbnail bytes exist (flags otherwise zero). A thumbnail DROPPED at the manifest bound keeps its bit clear — its record carries a real thumbLength and a later boot re-pushes it (the crash-resume value). The bit's header comment now documents both setters.
- **Files modified:** src/image_tx_manager.cpp, include/sd_store_balloon.h
- **Verification:** builds 2/2 + harness exit 0; the semantics are the rescan's both-bits skip working exactly as planned for thumbless captures.
- **Commit:** 7beb182 (same commit as Task 1)

### Plan-sanctioned notes (not deviations)

- RAM-slot release uses the plan's "or" alternative — freeEntry at the moment the delivery moments complete (SERVED site, after a successful FULL mark) — rather than extending sweepExpiredEntries. Trade-off named in code and here: a both-delivered image can no longer be tail-healed in-boot (rejected through the existing unknown/evicted NACK class; the base's D-24 pass machinery and the next-boot rescan are the recovery paths). Entries whose FULL flag write failed keep their slot for the TTL sweep.
- admitRescanned returns uint8_t (the plan's "e.g. void" gave latitude) so the resume summary line is exact.
- Torn detection for JPGs-without-META is a second memory-free walk pass — required by the plan's classification rule ("JPGs present without a validating META" must get the named line), unbounded-memory-free by construction.
