<objective>
Replace the browser-sensor antenna aiming with the operator's newly wired base-station hardware: a MAX-M10S-class GPS feeding NMEA into UART1 (GPS TX -> base RX on pin 45) and a QMC5883L compass on the existing I2C bus (pins 1/2, address 0x0D). The base firmware reads both sensors non-blocking, exposes position + true-north heading through a new /api/base endpoint (and a base block in /api/state), and the web UI's antenna pointing card and map observer marker consume that instead of the browser's device-orientation and position APIs — the monitoring tablet has no compass, so the hardware is now the only sensor source. Manual position and a new manual rig-tilt input remain as honest fallbacks.

Purpose: the antenna pointing feature's sensor half was the only part that depended on the tablet's own GPS/compass; this makes it work on any screen, from the rig's own sensors.

Output: updated base firmware + dashboard with hardware-driven aiming, both targets build green, single commit.

SCOPE NOTES:
- BALLOON UNIT UNTOUCHED — no balloon-side file changes; the balloon env's lib_deps is not edited. The in-flight D1 crash campaign needs the balloon build byte-identical.
- WHY A NEW ENDPOINT: the dashboard poll is 5 s (POLL_INTERVAL_MS 5000, main_basestation.cpp:897); a hand-turned Yagi needs a faster feedback loop, so /api/base is a tiny dedicated JSON (~150 B) polled at 1 s.
- KNOWN HARDWARE RISK (surfaced honestly, not silently accepted): the balloon's pin history (sensor_pins.h:35-48) records that pin 45 is the VDD_SPI strapping pad and "never received data" as a UART RX pin on the balloon board. The operator wired the base the same way anyway. This plan makes the failure VISIBLE (byte counter + [GPSBASE] line + "no fix" chip) and the rewire CHEAP (one editable constant, e.g. to free pin 47) — it does not silently claim pin 45 works.
- Discovery was Level 0/1 (all patterns exist in-tree): balloon GPS idiom in sensor_manager.cpp:134-147, shared I2C bus in status_display.cpp:34, QMC5883L driven register-level (init 0x0B=0x01 SET/RESET period, then 0x09=0x15 = OSR 512 / range 8 G / ODR 50 Hz / continuous mode; STATUS at 0x08 bit0 DRDY; six output bytes at 0x00, little-endian signed 16-bit) — no new compass library, mirroring the E32 register-level precedent.
</objective>
